# Инструкция по начальной настройке

**Конфигурация:** «Управление IT-фирмой» (доработка для компании «Ваш компьютерный мастер»)
**Новая функциональность:** подсистемы «Работа с заявками клиентов» и «Расчёт управленческой зарплаты», отчёты по ним

Инструкция предназначена для специалистов заказчика, которые переводят **рабочую информационную базу** (в ней уже ведётся реальный учёт в исходной конфигурации) на доработанную конфигурацию и подключают новые механизмы к работе.

> ⚠️ **Демонстрационная база из раздела Releases** (dt-файл с тестовыми данными) предназначена только для знакомства с функциональностью. **Не загружайте её в рабочую базу** — это удалит реальные данные.

---

## 1. Что добавлено в конфигурацию

Все добавленные объекты имеют префикс `ВКМ_` и находятся в служебной подсистеме `ВКМ_ДобавленныеОбъекты`.

| Подсистема | Что появилось |
|---|---|
| **Обслуживание клиентов** | Вид договора «Абонент»; документ «Обслуживание клиента»; регистр «Выполненные клиенту работы»; уведомления в Telegram; автозаполнение и печатная форма акта в «Реализации товаров и услуг»; обработка «Массовое создание актов» |
| **Расчёт управленческой зарплаты** | Документы «Начисление заработной платы», «Начисление фиксированных премий», «Выплата зарплаты», «График отпусков» (с формой «Анализ графика»); планы видов расчёта и регистры расчёта; регистры «Условия оплаты сотрудников», «Выполненные сотрудником работы», «Взаиморасчёты с сотрудниками» |
| **Отчёты** | «Выработка специалистов», «Анализ выставленных актов», «Расчёты с сотрудниками», «Расход запланированных отпусков» |

Добавлены дополнительные поставляемые профили групп доступа: «Специалист», «Менеджер», «Бухгалтер IT-фирмы», «Кадровик-расчётчик».

## 2. Порядок настройки (краткий чек-лист)

| № | Действие | Кто выполняет |
|---|---|---|
| 1 | Резервная копия и обновление конфигурации рабочей базы | Администратор |
| 2 | Проверка результатов обновления | Администратор |
| 3 | Назначение профилей групп доступа пользователям | Администратор |
| 4 | Создание номенклатуры и заполнение констант | Администратор, бухгалтер |
| 5 | Настройка уведомлений в Telegram | Администратор |
| 6 | Ввод договоров «Абонентское обслуживание» | Менеджер |
| 7 | Ввод условий оплаты сотрудников, проверка производственного календаря | Кадровик-расчётчик |
| 8 | Проверка (при необходимости — правка) макета акта | Бухгалтер |
| 9 | Контрольная проверка работы | Ответственный за внедрение |

> **Рекомендация.** Сначала выполните шаги 1–9 на **копии** рабочей базы, убедитесь, что всё работает, и только затем повторите на рабочей базе. Тестовые документы в рабочей базе не вводите.

## 3. Шаг 1. Резервная копия и обновление конфигурации

**Требования:** платформа «1С:Предприятие» версии 8.3.27 или выше; права администратора; для работы Telegram-уведомлений — доступ сервера 1С (в файловой базе — компьютера, на котором выполняются регламентные задания) в интернет.

1. Завершите работу всех пользователей.
2. Создайте резервную копию:
   - Конфигуратор → *Администрирование → Выгрузить информационную базу* (файл `.dt`);
   - для клиент-серверной базы дополнительно сделайте резервную копию на уровне СУБД.
3. Получите файл конфигурации `.cf` (формируется из проекта репозитория в 1C:EDT командой экспорта конфигурации).
4. Загрузите изменения в рабочую базу в Конфигураторе:
   - если в рабочей базе нет собственных доработок, кроме исходной конфигурации, — *Конфигурация → Загрузить конфигурацию из файла…*;
   - если в базе есть собственные доработки заказчика — *Конфигурация → Сравнить, объединить с конфигурацией из файла…* и аккуратно перенесите добавленные объекты и изменения существующих (изменения существующих методов выделены комментариями с префиксом `ВКМ_`).
5. Выполните *Конфигурация → Обновить конфигурацию базы данных* (F7), подтвердите реструктуризацию.
6. Запустите базу в режиме «1С:Предприятие» **под пользователем с полными правами**. Дождитесь завершения обработчиков обновления информационной базы (стандартные подсистемы выполнят их при первом запуске).

## 4. Шаг 2. Проверка результатов обновления

После первого запуска убедитесь, что:

- [ ] в журнале регистрации (*Администрирование → Обслуживание → Журнал регистрации*) нет ошибок, связанных с обновлением;
- [ ] в панели разделов появились новые подсистемы с соответствующим содержанием;
- [ ] в списке профилей групп доступа (*Администрирование → Настройки пользователей и прав → Профили групп доступа*) есть четыре профиля в папке «Дополнительные профили»: «Специалист», «Менеджер», «Бухгалтер IT-фирмы», «Кадровик-расчётчик». Если профили не появились, обновите поставляемые профили командой в списке профилей;
- [ ] в планах видов расчёта присутствуют предопределённые виды расчёта: оклад, процент от выполненных работ, отпускные, фиксированная премия, НДФЛ.

## 5. Шаг 3. Назначение профилей групп доступа

Профили групп доступа — **поставляемые**, их не следует изменять напрямую (при следующем обновлении изменения могут быть потеряны). Если нужны особые права — создайте собственный профиль на основе поставляемого.

1. Откройте *Администрирование → Настройки пользователей и прав → Группы доступа*.
2. Для каждого профиля создайте группу доступа (кнопка «Создать»), выберите профиль и добавьте участников — пользователей или группы пользователей.
3. Попросите пользователей перезапустить программу — новые права вступают в силу при следующем входе.

| Профиль | Кому назначить | Что доступно |
|---|---|---|
| **Специалист** | Сотрудники, выезжающие к клиентам | Документ «Обслуживание клиента», прикрепление файлов, отчёт «Выработка специалистов» |
| **Менеджер** | Сотрудники, принимающие заявки | Документ «Обслуживание клиента» (ввод и планирование заявок) |
| **Бухгалтер IT-фирмы** | Бухгалтеры | Обработка «Массовое создание актов», автозаполнение и печать акта в «Реализации товаров и услуг», отчёт «Анализ выставленных актов» |
| **Кадровик-расчётчик** | Сотрудники, ведущие зарплату и отпуска | «Условия оплаты сотрудников», «Начисление заработной платы», «Начисление фиксированных премий», «Выплата зарплаты», «График отпусков» (с анализом графика), отчёты «Выработка специалистов», «Расчёты с сотрудниками», «Расход запланированных отпусков» |

Дополнительно проверьте:

- один пользователь может входить в несколько групп доступа (например, руководитель-менеджер и специалист);
- у бухгалтера сохраняются права на документ «Реализация товаров и услуг», справочники контрагентов, договоров и номенклатуры из исходной конфигурации (при необходимости оставьте ему и его прежний профиль);
- константы с токеном Telegram-бота и идентификатором группы должен редактировать **только администратор**.

## 6. Шаг 4. Номенклатура и константы

### 6.1. Номенклатура

В справочнике «Номенклатура» создайте (или выберите существующие) две позиции вида «Услуга»:

- **«Абонентская плата»** — для строки с ежемесячной абонентской платой;
- **«Работы специалиста»** — для строки с оплатой выполненных работ по часам.

Ставку НДС и счета учёта укажите в соответствии с учётной политикой предприятия.

### 6.2. Константы

 Заполните четыре константы:

| Константа | Что указать | Для чего используется |
|---|---|---|
| **Номенклатура абонентской платы** | Позиция «Абонентская плата» | Автозаполнение «Реализации товаров и услуг» |
| **Номенклатура работ специалиста** | Позиция «Работы специалиста» | Автозаполнение «Реализации товаров и услуг»; отчёт «Анализ выставленных актов» (фактически выставленная сумма) |
| **Токен управления телеграм-ботом** | Токен бота (см. шаг 5) | Отправка уведомлений |
| **Идентификатор группы для оповещения** | Идентификатор Telegram-группы (см. шаг 5) | Отправка уведомлений |

> Если хотя бы одна из констант номенклатуры не заполнена, команда «Заполнить» в «Реализации товаров и услуг» выдаст ошибку и не заполнит документ.

## 7. Шаг 5. Уведомления в Telegram

При создании заявки или изменении даты, времени или специалиста в документе «Обслуживание клиента» программа сохраняет сообщение в справочнике «Уведомления телеграм-боту для отправки». Регламентное задание отправляет сообщения в группу и после успешной отправки удаляет их из справочника.

### 7.1. Создание бота

1. В Telegram найдите бота **@BotFather**, отправьте команду `/newbot` и следуйте подсказкам.
2. Скопируйте выданный **токен** (строка вида `123456789:AAE…`) и внесите его в константу «Токен управления телеграм-ботом».

> Токен даёт полный контроль над ботом. Не передавайте его посторонним, не публикуйте в репозитории и не отправляйте по открытым каналам.

### 7.2. Группа для оповещений

1. Создайте группу в Telegram и добавьте в неё специалистов и созданного бота.
2. Узнайте идентификатор группы: отправьте в группе любое сообщение, затем откройте в браузере адрес `https://api.telegram.org/bot<токен>/getUpdates` и найдите в ответе значение `chat → id`. Для групп это, как правило, **отрицательное число** (например, `-1001234567890`), знак «минус» вносится в константу вместе с числом.
3. Внесите идентификатор в константу «Идентификатор группы для оповещения».

### 7.3. Доступ в интернет

Компьютер или сервер, на котором выполняются регламентные задания, должен иметь доступ к `api.telegram.org` по порту 443. Если выход в интернет организован через прокси-сервер, укажите его параметры в настройках программы (*Администрирование → Интернет-поддержка и сервисы → Параметры прокси-сервера*) или обратитесь к системному администратору.

### 7.4. Регламентное задание

1. Откройте *Администрирование → Обслуживание → Регламентные и фоновые задания*.
2. Найдите задание отправки уведомлений Telegram-боту, установите флажок **«Включено»** и настройте расписание (рекомендуется запуск раз в 1–5 минут).
3. Для клиент-серверной базы задание выполняется на сервере 1С. Для файловой базы — в сеансе компьютера, на котором включено выполнение регламентных заданий.

### 7.5. Проверка

1. Создайте тестовый документ «Обслуживание клиента» и запишите его.
2. В справочнике «Уведомления телеграм-боту для отправки» должен появиться новый элемент.
3. Дождитесь запуска регламентного задания (или запустите его вручную) — сообщение придёт в группу, а элемент справочника получит пометку на удаление.
4. Если сообщение не пришло, а элемент остался в справочнике, см. раздел «Типичные проблемы» и журнал регистрации.

## 8. Шаг 6. Договоры на абонентское обслуживание

Выполняет менеджер (или другой сотрудник с доступом к договорам).

1. Откройте справочник «Договоры контрагентов» и создайте договор для каждого клиента, обслуживаемого по абонентской схеме (или измените вид существующего договора).
2. В поле **«Вид договора»** выберите **«Абонентское обслуживание»** — на форме станут доступны дополнительные реквизиты:
   - **дата начала действия договора**;
   - **дата окончания действия договора**;
   - **сумма ежемесячной абонентской платы** (может быть нулевой — тогда строка абонентской платы в акт не попадёт);
   - **стоимость часа работы специалиста**.
3. Обязательно заполните стоимость часа: по ней рассчитывается сумма к оплате клиентом в регистре «Выполненные клиенту работы».

Правила, о которых нужно знать:

- документ «Обслуживание клиента» проводится **только** по договору вида «Абонентское обслуживание», а его дата должна лежать **в периоде действия договора** (включая границы);
- не забывайте вовремя продлевать срок действия договоров — иначе документы по ним провести не удастся;
- договоры других видов (существующие записи исходной конфигурации) остаются без изменений.

## 9. Шаг 7. Сотрудники и условия оплаты

Выполняет кадровик-расчётчик.

### 9.1. Сотрудники

Убедитесь, что в справочнике сотрудников есть все специалисты и административные сотрудники, которые будут участвовать в расчёте зарплаты и планировании заявок.

### 9.2. Условия оплаты сотрудников

Регистр сведений «Условия оплаты сотрудников» — периодический (период — **месяц**). Для каждого сотрудника внесите запись, начиная с **первого месяца работы с новой функциональностью**:

- **Оклад** — для всех сотрудников;
- **Процент от работ** — только для **специалистов** (процент от оплаченных клиентом часов).

При изменении оклада или процента добавляйте новую запись с нужного месяца, прежние записи не удаляйте.

> **Важно.** Если на дату документа «Обслуживание клиента» для специалиста нет записи в регистре «Условия оплаты сотрудников», документ **не будет проведён**. Если запись есть и процент равен `0` — документ проведётся (работы будут учтены, процент специалисту начислен не будет).

### 9.3. Производственный календарь

Расчёт отпускных использует количество рабочих дней. Проверьте, что производственный календарь РФ загружен на текущий и предыдущий годы (подсистема «Календарные графики»), а график работы предприятия настроен.

### 9.4. Начальные данные и дата начала работы

- Рекомендуется начинать использование с **первого числа месяца**.
- Отдельного документа ввода начальных остатков по взаиморасчётам с сотрудниками не предусмотрено. Поэтому лучше начинать с месяца, за который все прежние начисления уже выплачены; иначе введите соответствующие документы «Начисление заработной платы» и «Начисление фиксированных премий» за прошлые периоды.
- Отпускные считаются из среднедневного заработка за последние 12 месяцев. В первый год работы в программе истории начислений ещё нет. Если нужен точный расчёт, введите документы начисления за предшествующие месяцы.
- Если требуется учесть уже выполненные работы клиентам за прошедшие месяцы, введите документы «Обслуживание клиента» с их фактическими датами (договор должен действовать на эти даты, а условия оплаты специалиста — быть заданы на них).

## 10. Шаг 8. Макет акта об оказанных услугах

Печатная форма акта (команда «Печать» в «Реализации товаров и услуг») содержит номер и дату документа, данные контрагента, организации и договора, детализацию по строкам, итог цифрами и прописью, поля для подписей и печати.

Если необходимо изменить вид акта (реквизиты, логотип, форма подписи), отредактируйте макет: *Администрирование → Печатные формы, отчёты и обработки → Макеты печатных форм* — выберите макет акта и измените его (понадобятся права на редактирование макетов; изменённый макет сохраняется в информационной базе и не теряется при обновлении). Для возврата к исходному макету используйте команду «Использовать стандартный макет».

---

## 11. Шаг 9. Контрольная проверка

Проверьте работу механизмов на **копии рабочей базы** (или на заранее согласованных данных).

1. **Договор.** Создайте договор «Абонентское обслуживание» с периодом действия, абонентской платой и стоимостью часа.
2. **Обслуживание клиента.** Создайте документ: клиент, договор, специалист, дата, плановое время, описание проблемы. Запишите — в группе Telegram должно появиться уведомление. Измените время и запишите ещё раз — должно прийти второе уведомление.
3. **Выполненные работы.** Заполните табличную часть (описание, фактические часы, часы к оплате), прикрепите файл (скан листа учёта) и проведите. Проверьте движения по регистрам «Выполненные клиенту работы» и «Выполненные сотрудником работы». Попробуйте провести документ по договору другого вида или с датой вне периода действия — должна появиться ошибка.
4. **Реализация товаров и услуг.** Создайте документ по абонентскому договору и нажмите «Заполнить» — должны появиться строка абонентской платы и строка с работами специалистов за месяц. Распечатайте акт.
5. **Массовое создание актов.** Откройте обработку, выберите месяц, выполните заполнение и создание. Повторный запуск за тот же месяц не должен создавать вторые реализации.
6. **Начисление заработной платы** за месяц: проверьте начисление оклада, процента от работ и удержание НДФЛ (13 %).
7. **Начисление фиксированных премий:** премия и НДФЛ.
8. **Выплата зарплаты:** табличная часть автозаполняется по остаткам взаиморасчётов на дату документа.
9. **График отпусков.** Введите отпуска; строки сотрудников с суммарным отпуском более 28 календарных дней подсвечиваются. Откройте «Анализ графика» — отобразится диаграмма Ганта.
10. **Отчёты.** Сформируйте все четыре отчёта за период, в котором есть проведённые документы, и убедитесь, что данные соответствуют документам.

После проверки на копии повторите настройку в рабочей базе (шаги 1–8) — без ввода тестовых документов.

## 12. Типичные проблемы

| Симптом | Возможная причина | Что делать |
|---|---|---|
| «Обслуживание клиента» не проводится: ошибка по договору | Выбран договор другого вида, или дата документа вне периода действия | Выберите договор «Абонентское обслуживание» или исправьте период его действия |
| «Обслуживание клиента» не проводится: не установлен процент | Нет записи в регистре «Условия оплаты сотрудников» на дату документа | Внесите запись (при необходимости с процентом `0`) |
| Сумма к оплате равна нулю | В договоре не заполнена стоимость часа | Заполните стоимость часа специалиста в договоре и перепроведите документ |
| «Заполнить» в «Реализации» выдаёт ошибку о номенклатуре | Не заполнены константы номенклатуры | Заполните константы (шаг 4) |
| «Заполнить» в «Реализации» не работает | Договор не вида «Абонентское обслуживание» | Выберите договор нужного вида |
| Уведомления не уходят, элементы копятся в справочнике | Задание выключено; неверный токен или идентификатор группы; бот не добавлен в группу; нет доступа в интернет | Проверьте шаги 5.1–5.4, посмотрите сообщения в журнале регистрации |
| Пользователь не видит документ, отчёт или раздел | Пользователь не включён в группу доступа с нужным профилем | Шаг 3; после изменения перезапустите программу |
| Отчёт пуст | Документы не проведены или нет движений по регистрам за период | Проведите документы, проверьте период отчёта |
| Не рассчитываются отпускные | Нет производственного календаря или данных за предыдущие месяцы | См. раздел 9.3 и 9.4 |

## 13. Регулярная работа (краткая памятка)

| Периодичность | Действие | Кто |
|---|---|---|
| Постоянно | Приём заявок и ввод документов «Обслуживание клиента»; внесение выполненных работ и скана листа учёта | Менеджер, специалист |
| Начало месяца | Массовое создание актов по абонентским договорам за прошедший месяц | Бухгалтер |
| Ежемесячно | «Начисление заработной платы», «Начисление фиксированных премий» (при необходимости), «Выплата зарплаты» | Кадровик-расчётчик |
| Начало года | Составление «Графика отпусков» и проверка загрузки в «Анализе графика» | Кадровик-расчётчик |
| При изменении условий | Новая запись в «Условиях оплаты сотрудников»; продление договоров | Кадровик-расчётчик, менеджер |
